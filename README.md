# data09-26 · 인증법규 Agent

건설기계 인증법규 문서를 조항 단위로 나눠 근거를 찾고, 근거가 있을 때만 답하며 AI 답의 문장마다 인용을 대조하는 근거 한정(Zero-Hallucination) RAG 브라우저 도구 — 사내 PC 에서 설치 없이, 사내 LLM(OpenAI 호환 주소)을 연결해 쓸 수 있음

| 항목 | 내용 |
|---|---|
| 제출자 | 이기욱 |
| 과정 | 현장 데이터 수집·디지털화 전문가과정 1차수 (2026) |
| 진행 단계 | 1단계 개발 완료 (2026-09-30) — https://aebonlee.github.io/data09-26/ |
| 다음 개발 | 2단계 — 실제 문서 · 질문으로 판정 기준 조정, M365 폴더 연동, 팀 공유, 검증 강화, Python · 팔란티어 운영 |

> 같은 제출자의 두 번째 과제입니다(첫 과제: [data09-15 기술표준 검토의견 작성 Agent](https://github.com/aebonlee/data09-15), 폐쇄망 로컬 Python 도구).
> 이 도구도 폐쇄망을 전제로 만들었습니다 — 인터넷 · 서버 · 외부 CDN 없이 `index.html` 더블클릭으로 돕니다.

## 실행 방법

**온라인에서 바로 보기: https://aebonlee.github.io/data09-26/**

처음 열면 「지식 문서」 화면입니다. **「가상 샘플 규정으로 시작」** 을 누르면 가상 규정 6개(알파국 · 베타국 · 감마연합 — 실제 법규가 아니며 숫자도 지어낸 것)가 들어가고, 예시 질문 버튼으로 네 가지 경우를 볼 수 있습니다.

| 예시 질문 | 보이는 것 |
|---|---|
| 알파국에서 굴착기 입자상물질 배출 기준은? | 근거 충분 → 근거 조항 [E1]~ → 프롬프트 → 답 검증 |
| 베타국 굴착기 소음 허용 수준은? | 절 번호형 문서(3.1)에서 근거 |
| 시험 성적서 보관 기간은? | 나라가 없어 「어느 국가 기준으로?」 되묻기 |
| 독일에서 굴착기 배출가스 기준은? | 「근거 없음 — 인증팀 확인 필요」 (AI 를 부르지 않음) |

폐쇄망 PC 에서는 이 저장소를 「Code → Download ZIP」으로 받아 풀고 `index.html` 을 더블클릭하면 됩니다. 문서와 질문은 이 브라우저 안에만 저장되고 어디로도 보내지 않습니다.

| 화면 | 하는 일 |
|---|---|
| ① 질문하기 | 질문 → 국가 · 분야 조건 읽기(직접 고를 수도) → 조건에 맞는 운영 문서에서 검색 → 근거 판정(충분 · 일부 · 근거 없음 · 되묻기, 이유 표시) → 근거 조항 카드(조항 · 쪽 · 개정일 · 시행일 · 출처 · 주의) → 근거 한정 프롬프트(복사, 선택: 설정한 AI 서버로 보내기) → **답 검증**(문장마다 인용 · 인용 실재 · 숫자 대조, 통과 문장만 보여 주기) → 답이 있는 후속 질문 · 도움됨 · 오답 신고 |
| ② 지식 문서 | PDF(글자 층) · Word(.docx) · .txt · .md · 붙여 넣기 → 나누기 미리보기 → 메타데이터(문서 코드 · 국가 · 인증 분야 · 개정일 · 시행일 · 상태 · 출처) → 넣기. 문서별 조각 목록 · 고치기 · 지우기 |
| ③ 기록 · 미응답 | 모든 질문의 판정 · 근거 조항 ID · 답 검증 · 피드백. 근거 없음 · 표시됨 · 오답 신고 · 되묻기로 거르기, 근거가 없던 낱말 집계, CSV |
| ④ 골든셋 점검 | 「질문 \| 정답 조각 ID」 · 「질문 \| 거절」 줄로 적어 AI 없이 정답 조항 재현율(Recall@K)과 정직한 거절률을 잼 |
| 설정 | 판정 기준(상위 K · 충분/일부 비율 · 최소 점수 · 오래된 자료 · 구버전 포함), AI 연결(OpenAI 호환 주소 · 모델 · 본인 키, 기억은 선택), 선택: 벡터 검색(`/embeddings`), JSON 백업 |

- 로직 테스트: `node test/logic.test.mjs` (의존성 없음)
- 샘플 글 파일 다시 만들기: `node scripts/make-samples.js` → `samples/*.txt · *.md` (PDF · Word 샘플은 같은 글로 만든 파일)
- DB 스크립트 검증: `./scripts/sqltest/run.sh` (로컬 PostgreSQL 필요)

## 근거 없으면 답하지 않는 구조 (1단계)

| 방어선 | 이 도구에서 |
|---|---|
| 폐쇄 지식 | 넣어서 「운영」으로 둔 문서만 근거로 씀. 구버전은 설정에서 켤 때만(「구버전」 표시) |
| 조항 단위 나누기 | 제N조 · ①항 · 부칙 / 3.1 절 · 부속서 A.1 / # 제목 / 문단 — 자동 판별. 조각 ID = 「문서코드 조항」 |
| 근거 판정 | 질문의 핵심 낱말이 근거에 있는 비율 · 검색 점수 · 없는 나라 → 미달이면 AI 를 부르지 않고 고정 문구 「근거 없음 — 인증팀 확인 필요」 |
| 근거 한정 생성 | 근거 조항만 넣은 프롬프트, 모든 문장에 [E번호], 숫자 원문 그대로, 근거 안 지시문 무시 |
| 사후 검증 | 인용 없는 문장 · 이번 근거에 없는 인용 · 인용한 조항에 없는 숫자를 표시하고 빼며, 남는 문장이 없으면 전체 거절 |
| 시간 유효성 | 시행 전 · 오래된 자료 · 구버전 주의를 근거와 프롬프트에 표시 |
| 사람 확인 | 모든 질의 기록, 오답 신고, 근거 없음 낱말 집계, 골든셋 |

LLM 의 오류를 이론적으로 0 으로 만들 수는 없으므로(제출 원문의 「정직한 전제」), 이 도구는 의사결정 지원용입니다. 최종 인증 판단과 대외 제출은 인증팀 확인이 원칙입니다.

## 1단계 구현 범위

| 요청 | 상태 | 1단계에서 한 것 / 남은 것 |
|---|---|---|
| 할루시네이션 0 근접 | 완료(구조) | 위 방어선. 문장 함의 검사 · 검증용 LLM 분리는 2단계 |
| 「없음」 답 + 되묻기로 구체화 | 완료(국가 되묻기 · 후속 질문) | 기종 · 판매 시점 되묻기는 메타데이터 확장 후 |
| 지식 폴더 기능 | 완료(파일 넣기 · 메타데이터 · 상태) | M365 폴더 자동 연동은 2단계 |
| Python · 팔란티어 / 사내 PC 운영 | 사내 PC(브라우저) 완료 | 로직 분리 — 운영 환경 확정 후 이식(기획서 10장) |
| 사외 링크 · 사내 시스템 | 출처 칸만 | 스냅샷 · 연동은 형태 확인 후 |
| 팀 공유 | 2단계 | DB 스키마 · 검증 하네스는 준비됨 |
